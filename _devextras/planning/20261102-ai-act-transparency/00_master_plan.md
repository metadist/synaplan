# AI Act transparency — people know it is an AI, and machines can tell what it made

Row 36. Umbrella: [`20261102-enterprise-readiness/`](../20261102-enterprise-readiness/00_master_plan.md) (C7–C9).

Article 50 of the AI Act has applied since **2026-08-02**. Systems that
were already on the market before that date must mark generated content
machine-readably by **2026-12-02** (to be confirmed by counsel, D1). Two
obligations hit Synaplan directly, and one hits every customer:

| Article | Who | Obligation | Synaplan today |
| ------- | --- | ---------- | -------------- |
| 50(1) | Provider of a system that talks with people | People are told they interact with an AI, at the latest at the first interaction, unless it is obvious | Widget: yes. Mail, WhatsApp, Telegram: no |
| 50(2) | Provider of a system that **generates** image, audio, video or text | Output is marked in a machine-readable format and detectable as artificially generated | No marking. Files are stored as the provider sends them, and some paths re-encode them, which drops the provider's mark |
| 4 | Every provider **and deployer** | Staff who operate or use AI have sufficient AI literacy (enforced from 2026-08-02) | Nothing that helps a customer prove it |
| 50(4) | Deployer | Deepfakes, and AI text published on matters of public interest, are labelled | Customer's duty; Synaplan can make the label one click |

The final EU Code of Practice on transparency of AI-generated content
(June 2026) makes the expected state of the art concrete:

- Image, audio and video get **two layers**: digitally signed, time-stamped, tamper-evident metadata plus an imperceptible watermark.
- Free-form text gets one layer: a watermark above 200 tokens, which only the model provider can apply.
- Watermark detection must be interoperable by **2027-02-02**.
- For digitally signed metadata, C2PA Content Credentials is the practical standard: a `c2pa.created` action with IPTC `digitalSourceType = trainedAlgorithmicMedia`.

This plan does not make Synaplan a high-risk system and does not
classify customer use cases. Those stay with the deployer (`docs/AI_ACT.md`, AT0).

## 2. What is fine — do not "fix" it

- The widget notice exists at first contact and is tested (`data-testid="privacy-notice"`). It stays dismissible per visitor; dismissal happens after it was shown.
- The user's own chat in the web app, Desktop and mobile is a context where AI is obvious (50(1) exception). No extra banner there.
- Text generated by LLMs is watermarked (if at all) by the model provider. Synaplan does not rewrite model text to add one (D4).

## 3. Target model

### 3.1 Disclosure (50(1)) — one sentence, every channel where a third party talks to the AI

| Channel | Where | Default sentence (en) | Owner override |
| ------- | ----- | --------------------- | -------------- |
| Widget | the existing notice | "You are chatting with an AI assistant. Answers can be wrong." + privacy link | Add a company name and a link; the AI sentence itself cannot be removed |
| Mail (inbound mail answered by an assistant) | footer of every AI-written reply | "This reply was written by an AI assistant of {sender}." | Text per mail handler; never empty |
| WhatsApp, Telegram | first reply of a conversation, and again after 24 h of silence | "Hi, I am {name}, an AI assistant." | Text per bot; never empty |
| Teams, Slack (row 39) | first reply per conversation | same as WhatsApp | same |

The text is stored per channel binding. One shared resolver,
`AiDisclosure::forChannel()`, returns the localized sentence, so there
is one place to test it. The language follows the conversation's
detected language, with the owner's locale as fallback.

### 3.2 Marking (50(2)) — Content Credentials on everything Synaplan generates

```text
provider bytes ─► GeneratedMediaStore::keep()
                  ├─ keep provider manifest (ingredient)        AT2
                  ├─ sign C2PA manifest via signer sidecar      AT3
                  │    c2pa.created, digitalSourceType=trainedAlgorithmicMedia,
                  │    softwareAgent = model name from BMODELS, ingredient = provider manifest
                  ├─ XMP/IPTC digitalSourceType where C2PA cannot embed   AT3
                  └─ invisible watermark (phase 2, D5)          AT7
               ─► register file (BFILES) with provenance columns          AT3
```

- **Signer runs out of process.** The private key never sits in the PHP app container. A small sidecar, `c2pa-signer`, wraps `c2patool` / `c2pa-rs` behind `POST /sign` (bytes + manifest JSON → signed bytes) and `POST /verify`. It is a `FeatureModule` under `Module/Sidecar/` beside Tika and Docling. When absent, media are stored as today plus the XMP fallback, and Admin → System status says "Generated media are not signed".
- **Model name is data.** `softwareAgent` comes from the model row (`BMODELS` name + provider), never a literal.
- **Provider marks survive.** If the provider bytes carry a manifest, it becomes the ingredient of ours (`--parent`). No step in the pipeline re-encodes a generated original. Derived files (thumbnails, Office embeds, Telegram voice) get their own manifest with `c2pa.converted` / `compositeWithTrainedAlgorithmicMedia`.
- **Certificate.** Phase 1 uses a metadist signing certificate (D2). Verifiers show it as "valid, issuer not on the trust list" until a C2PA-conformant CA certificate is bought. The `digitalSourceType` signal works either way.
- **Provenance on the file row.** New nullable columns on `BFILES`: `BGENERATED` (bool), `BGENMODEL` (model id), `BCREDENTIALS` (none / signed / provider / both). Migration with raw idempotent `addSql`, the Galera rule.

### 3.3 AI literacy (Art. 4) — material plus a record, off by default

- **Help → "Using AI well".** Ten short sections, five locales: what a model is, wrong answers, sources, personal data, sovereignty settings, prompts, approvals, bias, when not to use AI, who to ask. Static content in `frontend/src/content/ai-literacy/`.
- **An administrator can require confirmation** (`AI_LITERACY.REQUIRED`, BCONFIG, default off). Users then see one card on their next sign-in: "Your organisation asks you to read 'Using AI well' (8 minutes)." Actions: **Read now** and **Remind me tomorrow**. There is no hard block (D6).
- **Record.** `BAI_LITERACY_ACK` (`BUSERID`, `BVERSION`, `BCONFIRMED`). Admin → People shows a column and offers a CSV export: "34 of 40 people confirmed version 2026-11". Changing the version asks everyone again. The record is erased with the account (`Erasure/`).

## 4. Decisions

- [ ] **D1 (AT1, AT3).** Counsel confirms the dates (50(2) for systems already on the market: 2026-12-02) and the role split: metadist is the provider for `web.synaplan.com`, the self-host operator for their install. AT1 and AT3 ship before 2026-12-02 regardless.
- [ ] **D2 (AT3).** Phase 1 signing certificate: metadist self-issued (free, "untrusted issuer") now. A C2PA-conformant CA certificate is bought when ER3 starts.
- [ ] **D3 (AT3).** Signer as a sidecar image `ghcr.io/metadist/synaplan-c2pa-signer` (Rust `c2patool`, about 20 MB). The alternative is the `c2patool` binary inside `synaplan-base-php` — rejected: it puts the key next to PHP and couples base-image releases. This is a new compose service and image, so it is the owner's call (AGENTS.md "Docker/CI").
- [ ] **D4.** No watermarking of LLM text by Synaplan. Disclosure covers text, and the model provider owns the text watermark.
- [ ] **D5 (AT7).** Invisible watermark for images, phase 2, before 2027-02-02: Adobe TrustMark (MIT, open source, Python) in the same signer sidecar, with detection exposed at `/verify`. The alternative is to wait for a consortium detector under the Code.
- [ ] **D6 (AT6).** The literacy confirmation never blocks work. It is a card with a reminder, not a gate.
- [ ] **D7 (AT1).** Mail disclosure is a footer on every AI-written reply, not only the first, because mail threads are forwarded.

## 7. Risks

| Risk | Mitigation |
| ---- | ---------- |
| The footer annoys customers in long mail threads | D7 explains why. The text is editable, a single line and not a banner |
| CDN or image optimiser strips the manifest | Originals are served as stored (AT2 test). `docs/AI_ACT.md` tells operators not to put an image optimiser in front of `/api/v1/files/uploads/` |
| Signing adds latency to generation | Signing happens on the worker after `keep()` (same job), measured in AT3. Budget ≤ 300 ms per image; video is signed in streaming mode |
| Untrusted certificate confuses people | AT4 copy says "signed by Synaplan" and does not claim "verified". D2 upgrades the certificate |
| Date or role reading is wrong | D1 counsel check. AT1 and AT3 are right under any reading |

## 8. Non-goals

- Classifying customer use cases as high-risk, or conformity assessments.
- Watermarking model text.
- Detecting AI content uploaded by users, beyond showing an existing manifest in AT4.
