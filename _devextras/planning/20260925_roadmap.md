## 4. Row 2 — openDesk meeting notes (Jitsi), minimum

**One sentence:** Synaplan offers a tool that transcribes a Nordeck/Jitsi
conference call by taking the participants’ voice streams from the
conference bridge, sending them to Synaplan speech-to-text, and writing
one transcript into a storage space the operator chose.

This is the **minimum**. The full product — Element voice notes, Element
Call live captions, Nextcloud + Element notices — stays planned in
[`04_opendesk_audio_transcriber.md`](./20260917-backend-integrations/04_opendesk_audio_transcriber.md)
and will be expanded after this lands. Nothing below contradicts that
plan; it cuts it.

### 4.1 What openDesk runs (short)

Chat and 1:1 calls are **Element** (Matrix); meetings are **Jitsi**
(Nordeck-supported); files are **Nextcloud**. Jitsi’s bridge (JVB) can
hand per-speaker audio to an external transcriber over a WebSocket;
Jigasi transcription is deprecated and only matters for SIP. So v1
listens to the bridge, not to a SIP leg and not to a bot participant.

### 4.2 Minimum architecture

```text
Jitsi Meet ── Jicofo ── JVB ─── per-speaker audio (Opus) ───▶ synaplan-opendesk-transcriber
                                                                (decode · window · VAD · speaker tag)
                                                                            │
                                            POST /v1/audio/transcriptions/sessions/{id}/audio
                                                                            ▼
                                                              Synaplan STT (whisper.cpp or catalog)
                                                                            │
                                                 session.done ──▶ one Markdown file in the storage space
```

| Part | Minimum | Repo |
| ---- | ------- | ---- |
| Sidecar `synaplan-opendesk-transcriber` | Speaks the transcription dialect Jitsi ships; one session per meeting; one audio channel per participant with the Jitsi display name as speaker tag; VAD + 5–10 s windows; forwards to the Synaplan **sessions** STT API that already exists (`docs/OPENAI_COMPATIBLE_API.md`); no audio kept on disk. | new sibling repo |
| Synaplan module `opendesk_stt` | `FeatureModule` (default **off**; decisive env `OPENDESK_STT_ENABLED` + scoped key). One webhook `session.done` → writes `Meetings/<date>-<room>.md` (speaker-tagged, timestamps) into the **storage space**; audit `opendesk_stt.started / stopped / saved`. No Matrix, no XMPP in PHP. | `synaplan` |
| Storage space (v1) | A **Synaplan Files folder** owned by the account that holds the connection key, chosen at setup. It is already findable (Files, ten seconds), shareable with a group (IAM), and searchable by the AI (Sources). Nextcloud folder as target is the first expansion (OD-A3). | existing |
| Setup surface (v1) | Reuse **Developer & devices → API keys**: create a key with scope `stt:sessions` + `files:write`, pick the STT model and the folder, copy the Jicofo / `config.js` snippet the form emits. The Integrations catalog card (BI1, row 3) replaces this later and must not be waited for. | `synaplan` |
| In the meeting | Moderator **Start notes** / **Stop** (Jitsi’s existing transcription toggle); banner for everyone: “Notes are on. Stop anytime. Audio is not kept.” Live captions in Jitsi only if the dialect gives them for free; otherwise v1.1. | Jitsi config |
