## 6. Wave 6 — Backend integrations

**Intent:** a developer or an openDesk admin points **their** Synaplan at
the tools they already use, the way Claude Code takes
`ANTHROPIC_BASE_URL` + a key. Synaplan is the account, the models, RAG,
STT/TTS, and audit. The other product is the hands.

We already have the faces. Wave 6 makes them a **collection**, not a
scavenger hunt:

| Face | Today | Wave 6 |
| ---- | ----- | ------ |
| Anthropic Messages `POST /v1/messages` | Claude Code, Desktop | Same, plus editor plugins |
| OpenAI `POST /v1/chat/completions` + `/v1/models` | Collabora plan, generic SDKs | Catalog lists every consumer |
| OpenAI `POST /v1/audio/transcriptions` + **sessions** | Docs exist; unused by partners | openDesk + voice notes |
| Native `/api/v1/*` + OpenAPI / Zod | Nextcloud, OpenCloud, Synamail | Shared “Connect an app” form |
| MCP | Flag-gated | One card in the catalog |
| Platform-links handshake | Outlook + Nextcloud S1 | Reused, not rewritten |

### 6.1 Product surface (in this repo)

One **Integrations** page (Developer & devices, next to API keys and
Coding clients — NV06 already made that group). Not a new rail item.

Each catalog card answers the five questions on the open surface (U7):

1. Who owns this connection?
2. Who else can use it?
3. Which Synaplan models / capabilities does it touch?
4. How do I stop it?
5. Where did it come from?

Empty state: one sentence + **Connect an app**. Flag off ⇒ the card is
absent (U11). Model selection is a real picker (chat, STT, embeddings),
not a raw provider id. The form emits the snippet the other tool needs
(`ANTHROPIC_BASE_URL`, OpenAI `base_url`, Matrix bot env, Jitsi
`url-template`).

## 7. openDesk audio — what the product actually is

openDesk does **not** use Nextcloud Talk for chat.

Official split ([openDesk product](https://www.opendesk.eu/en/product),
[architecture](https://docs.opendesk.eu/operations/architecture/)):

| Job | Component | Notes |
| --- | --------- | ----- |
| Chat + 1:1 / small-group voice and video | **Element Web + Synapse** (Matrix), Nordeck widgets | Element Call / **MatrixRTC + LiveKit** for media |
| Meetings / conferences | **Jitsi** (Nordeck-supported) | Jigasi only for SIP dial-in, not the default transcriber |
| Files | Nextcloud | Where the transcript file should land |
| Weboffice | Collabora | Separate track |
| Mail / calendar | OX App Suite | Later: “file this transcript on my calendar” |
| IAM / portal | Nubus (Keycloak + OpenLDAP) | SSO for the Synaplan bot and the Integrations page |

Synaplan already has the STT API
(`docs/OPENAI_COMPATIBLE_API.md`: one-shot + streaming sessions) and
local whisper.cpp. Wave 6 wires that API into Element and Jitsi with
**consent, a stop button, and a findable transcript**.

The deep plan — threat model, E2EE limits, sprints, journeys J-OD-1…5 —
is [`04_opendesk_audio_transcriber.md`](./20260917-backend-integrations/04_opendesk_audio_transcriber.md).
Read it before any media-path code.

**v1 recommendation (locked unless STATUS records a change):** Jitsi
meetings first (JVB bridge-based transcription → Synaplan as the
OpenAI-compatible STT backend). Element voice messages second. Element
Call live captions third (bot must join as a visible participant).

## 8. Principles, UX, vocabulary

The eight 2026-09-03 principles still bind. U1–U12 still bind.

| Term (en) | Meaning | Not |
| --------- | ------- | --- |
| **Integration** | A packaged consumer of the Synaplan API (plugin, add-in, bot, extension) | A Synaplan `plugins/` in-process module, unless we say so |
| **Catalog** | The list of integrations + the Connect form | The model catalog (`BMODELS`) |
| **openDesk chat** | Element / Matrix | Nextcloud Talk |
| **openDesk meetings** | Jitsi | Element 1:1 calls |
| **Transcriber** | Synaplan STT used by Element or Jitsi | The TTS repo (`synaplan-tts`) |
| **Compute node** | Server that runs `synaplan-compute` | Desktop, even headless |

Banned in primary copy: MatrixRTC, LiveKit, JVB, Jigasi, MSC, SFU,
whisper.cpp, `base_url`. Those words stay in docs and Advanced.
